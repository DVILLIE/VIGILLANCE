# D'Vielle — User Operating Guide and Safety Workflows

Version 1.0 • 10 October 2026 • Guide for the proposed advancement release

## What this guide describes

This guide defines the intended operating experience for the advancement design. Screens/actions described here are not all verified in the current application. Use the existing USER_GUIDE.md for historical behavior and verify the installed version. A final release guide must match actual tested controls before publication.

D'Vielle provides local observation, understandable findings and individually supported protection actions. Optional ethical assessment is for authorized assets. Installation does not authorize every future change.

## Start and understand status

Launch the trusted installed version. Review the version and capability summary. “Observation active” means sensors are running with stated coverage. “Effect verified” refers to a specific checked action. “Coverage unavailable” or “stale” means the application lacks current evidence for that capability.

A moving logo or device line is visual activity, not proof that malware was stopped. If an action cannot be supported on your Windows build, observation should remain available and the reason should be visible.

## Review a finding

Open the finding and read the observed facts, time/source and affected target. Expand the explanation for benign alternatives and remaining uncertainty. An unfamiliar connection is not automatically malicious. Compare the recommended action with the work you are doing.

If an action is proposed, review which executable/address scope it changes, what work may stop and how it can be restored. Decide whether to allow that exact action or a supported recurring policy. Do not approve broad access merely to remove an alert.

## Use automatic protection

Choose only the actions whose effects and recovery you understand. Previously accepted policies may run without asking again. Automatic protection should retain an activity record showing reason, target, authorization and result.

If a result is unknown, do not repeatedly click the same action. Open recovery status and allow the application to reconcile actual state. A failed action must not appear verified.

## Restore an application change

Review the operation's owned changes. Request restoration and read any reported conflict. An administrator or another application may have changed the same setting; the guardian should preserve that change rather than overwriting it silently.

If recovery requires assistance, export a selected redacted record. Do not disable antivirus/firewall globally as a workaround.

## Assess an authorized asset

Enter the asset scope, authority, allowed tests, exclusions, time window and rate limits. Confirm the target belongs to your authorized scope. Inventory/passive review is the initial default. Active tests require their explicit supported scope.

Stop prevents new actions; work already in progress may still require reconciliation. Reports must distinguish observed behavior from potential version-based findings. Do not use the application to test unrelated third parties.

## Privacy and diagnostics

Review retention and optional sharing. Documents, passwords and session tokens are not routine support inputs. Preview exports and remove identifying paths/endpoints when not needed. Keep recovery records until resolved; deleting them may prevent safe restoration.

Local deletion does not necessarily erase every backup or physical storage remnant. The application should describe the scope honestly.

## Accessibility and daily use

Use reduced-motion mode if effects are distracting. Essential status remains readable without animation, sound or color. Keyboard and screen-reader journeys must be tested in the released build. Report clipping or inaccessible controls as defects.

## Troubleshooting

If the helper is unavailable, observation may continue while actions are disabled. If a feed is stale, its data remains stale context. If the model is unavailable, accepted deterministic protection should remain. If local system trust is doubtful, follow independently obtained vendor/recovery instructions rather than relying solely on the affected system's status.

Use trusted signed updates only. A request to bypass verification or run a user-writable interpreter as administrator is not a normal repair step.

## History privacy and measured costs

Open Ethical Hacking, then Privacy & costs. Automatic cleanup starts off. Choose
the days/count settings and save the policy. Enabling automatic cleanup asks
for confirmation; saving itself deletes nothing. Preview cleanup lists up to
200 terminal history records. Delete previewed records requires a separate
confirmation. Running records are preserved. Exports/backups remain separate.

The same tab shows recorded assessment process-tree measurements. These are
checkpoint samples, not proof of whole-app performance or a hard resource cap.
Opening an older assessment shows its snapshot freshness; reobserve before
acting on old findings.

Use Check protection service to inspect actual installed prerequisites. A
missing or unreadable helper is not treated as active protection. This check
does not install, elevate or change Windows settings.
