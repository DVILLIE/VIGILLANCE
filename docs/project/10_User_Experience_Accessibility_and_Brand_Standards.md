# D'Vielle — User Experience, Accessibility and Brand Standards

Version 1.0 • 10 October 2026 • Proposed experience specification

## Brand and visual identity

User-facing product name is D'Vielle. The approved Quantum Key artwork remains the identity baseline: dominant D/V mark, cool-blue D edge effect and distinct blue/gold cube activity. The approved direction is preserved; this documentation does not alter artwork or animation.

Use “Intelligent Vigilance” as the concise descriptor and “Vigilia — Always Watching” where the alternative brand wording is intentionally used. Keep internal compatibility identifiers stable unless migration is explicitly designed.

## Information hierarchy

The main view answers: Is observation active? Which protection capabilities are available and verified? What needs attention? What changed? Can I recover it?

Show state through readable text and icons in addition to color. Keep device names, evidence age and unknown observations explicit. Separate observations from executed actions. A displayed network line represents a relationship view; movement is not proof of live packet activity.

## Interaction standards

A finding has a short factual explanation and expandable evidence. An action preview states exact target, scope, expected interruption and recovery. Prefer previously accepted policy over repetitive prompts, while new consequential authority receives an explicit decision.

Success messages distinguish accepted, applied and verified. Unknown outcomes open the recovery workflow. Controls explain disabled state and prerequisites. Avoid generic “all safe” statements when sensors are missing.

## Motion and visual safety

Provide a persistent reduced-motion/static mode. Pause decorative work when hidden or backgrounded and include all animation cost in the process-tree budget. Effects must not obstruct focus, reading or input.

Analyze lightning effects for actual flashing frequency, contrast and screen area; a five-second burst interval does not prove each burst meets flash guidance. [WCAG 2.2](https://www.w3.org/TR/WCAG22/) includes pause/stop/hide and flash criteria; animation from interaction is a Level AAA criterion. Apply relevant principles to native desktop design without claiming web conformance proves native accessibility.

## Native accessibility

Test keyboard navigation, focus visibility, accessible names/roles/states, Narrator behavior, high-contrast settings and Windows display scaling. Custom-drawn canvas elements require explicit accessible alternatives. If the toolkit cannot expose essential controls adequately, use a supported native accessibility bridge or revise the control implementation rather than declaring the feature accessible.

Essential content must remain available in text even when decorative rendering fails. Voice feedback remains optional and never the only error/status channel.

## Content and internationalization

Use short active language and consistent technical terminology. Translate product content through versioned message catalogs after English terms stabilize. Preserve IDs and protocol values across translations. Explain uncertainty without blaming users. Do not label ordinary software activity as espionage without evidence.

## Acceptance journey

A keyboard/screen-reader user must complete finding review, action decision, recovery and export without mouse-only controls. At supported scaling, text and buttons remain usable with no clipping of essential instructions. Reduced motion persists after restart. Color-blind review verifies state distinctions. Real users and assistive technology must be used before an accessibility claim.

These are proposed acceptance obligations; no accessibility certification or user study is claimed.
